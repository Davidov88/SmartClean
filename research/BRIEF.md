# SmartClean — совместный бриф

Дата: 4 ноября 2026. Исходный проектный бриф. Обновление: прототип 0.1 реализован и проверен; первые сканы C: и D: сохранены. Текущее поведение и ограничения описаны в ../README.md, измеренный выбор движка — ENGINE-DECISION.md.

## Принятое направление

Универсальная переносимая Windows-утилита с русским терминальным меню. Никакого браузера, web UI или сервера. Собственная небольшая оболочка и адаптеры готовых сканеров; собственный MFT-парсер на первом этапе не разрабатываем. Рабочие пути, буквы томов и имена пользователей не зашиваются в код. Windows 10 пользователя входит в проверяемую матрицу; фактическая совместимость и официальная поддержка runtime различаются.

При первом запуске обнаружить физические устройства, разделы и тома, связи между ними, тип носителя, файловую систему, ёмкость/занято/свободно. Неизвестные типы не угадывать. Не начинать полный обход автоматически. Предложить выбрать область и место результатов с достаточным свободным пространством.

## Исследование и взаимная проверка

Два агента независимо исследовали аналоги, затем прочитали отчёты друг друга и согласовали решения. Полные источники, ограничения и замечания:

- [Скорость и стабильность](performance-reliability.md).
- [Удобство и развитие](usability-evolution.md).

Сравниваем первыми gdu и WinDirStat 2.9.3. Microsoft Sysinternals DU — дополнительный независимый ориентир. dust и dua остаются резервными кандидатами и примерами UX. WizTree не включаем обязательной зависимостью: личное бесплатное использование не покрывает произвольное коммерческое применение и распространение. Everything требует внешнего установленного индекса. Собственный незрелый raw MFT-парсер не даёт необходимого выигрыша по риску/объёму проверки.

Первичные источники: [gdu](https://github.com/dundee/gdu), [WinDirStat README опубликованного тега](https://github.com/windirstat/windirstat/blob/release/v2.9.3/README.md), [DU Microsoft](https://learn.microsoft.com/en-us/sysinternals/downloads/du), [WizTree EULA](https://diskanalyzer.com/eula).

Это выбор кандидатов, не окончательный выбор движка. WinDirStat GPLv3+ требует соблюдения условий поставки; gdu MIT требует сохранения notices. Перед использованием закрепляются версии и проверяются артефакты. Документация релиза не доказывает работу без окон/диалогов на конкретном ПК.

## С чего начать

1. Зафиксировать небольшой контракт snapshot и способностей адаптера. Совместимый launcher/меню на PowerShell 5.1, горячий подсчёт отдельным процессом; окончательный runtime выбрать по проверке Windows, без обязательной установки PS7.
2. Подготовить контролируемый набор данных с известными размерами: обычные/мелкие файлы, глубокие и русские пути, hardlinks, junction наружу/цикл, sparse/compressed, недоступная ветка. Тесты нужны для реальной корректности, а не повторения реализации.
3. Проверить кандидатов: отсутствие веба и неожиданных окон, правильность учёта, ошибки, отмена, экспорт/импорт. Измерить время первого полезного результата, весь скан, память, размер отчёта и отзывчивость навигации. HDD/SSD учитывать по физическому устройству, не букве раздела.
4. Получить первый работающий сценарий: запуск → обнаружение → выбор тома → один read-only скан → три уровня дерева → раскрытие из сохранённых данных → сохранение/загрузка → второй замер → сравнение.
5. Только после этого подключить кандидатов на очистку, конкретные согласованные правила и исполнение. Это полная v1. Междисковые дубли и организация/переносы — v2.

После согласования брифа пользователь разрешил реализацию. Первый read-only сценарий реализован; очистка и переносы пользовательских данных пока не включены.

## Контракты

- InventoryProvider: устройства, разделы, тома, стабильные идентификаторы, точки монтирования, unknown.
- ScannerAdapter: capabilities, запрос, progress, cancel, записи, ошибки, итог. Read-only, без удаления.
- SnapshotStore: versioned manifest, неизменяемые снимки, запрос дочерних узлов, атомарная фиксация, контроль места и retention.
- DiffService: сравнение сопоставимой области/метрики/политики; отсутствующий том не считать удалёнными данными.
- CleanupRule + Planner: объяснение кандидата и план, стабильный id/version правила и условия.
- Executor: повторная проверка актуального пути/идентичности/ссылок/разрешения перед изменением; журнал по объектам.
- History: события, ошибки, результаты, происхождение данных. Меню/CLI/будущее окно используют одни сервисы.

Не строить сложный framework произвольных плагинов в прототипе. Контракты — компактные внутренние границы с версией формата.

## Обязательные свойства

- Три уровня — глубина вывода. Полный размер ветки включает более глубокие файлы; неполный подсчёт обозначается явно.
- Logical bytes и allocated bytes различаются; unknown не заменяется нулём. Junction на другой диск не увеличивает физическую сумму исходного. Hardlinks учитываются по принятой явно указанной политике.
- complete/partial/cancelled/failed, ошибки и пропуски видны. Сумма файлов не обязана совпадать с занятостью тома; разницу не называть мусором.
- Один проход обслуживает последующее углубление. Обновление ветки создаёт новое наблюдение со своим временем, не меняет старый снимок.
- Живая файловая система измеряется за интервал, не атомарно. Сохранение частичного результата не равно resume.
- Недельные снимки позволяют видеть устойчивый рост. Рост папки не доказывает процесс-виновник. Автоматическое расписание отдельно настраивается позже; сейчас не создаётся.
- Согласие на очистку привязано к категории, области и версии правила. Изменённое правило не расширяет старое разрешение молча. История чатов, профили, проекты и результаты не объявляются мусором по возрасту.
- Размер удалённых объектов и фактическое изменение свободного места показываются отдельно. Корзина на том же томе не гарантирует освобождения.
- Собственные снимки/логи ограничиваются retention, учитываются как расход SmartClean и явно исключаются из анализа роста при выбранной политике.

## Нерешённые вопросы для проверки

Какой движок проходит Windows-проверки allocated size, reparse points, hardlinks, отмены и экспорта без UI; сколько памяти и диска требует индекс; нужен ли отдельный индекс вместо импорта JSON. Ответ даст прототип и измерения. До них обещать идеальную работу на всех ПК или фиксированную скорость нельзя.
