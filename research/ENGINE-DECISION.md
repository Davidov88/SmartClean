# Выбор движка: измерения на Windows

4 ноября 2026. Это дополнение к исследованию: обе программы действительно запускались на одинаковом наборе файлов, а не только сравнивались по README.

## Среда и артефакты

Windows 10 x64, штатный Windows PowerShell 5.1. Тестовый каталог на NTFS HDD E:. gdu 5.38.0 и WinDirStat 2.9.3 portable скачаны с официальных GitHub releases; SHA-256 архивов совпал с опубликованным GitHub digest. Версии и хеши записаны в tools.lock.json. Официальная документация: [gdu](https://github.com/dundee/gdu/tree/v5.38.0), [WinDirStat](https://github.com/windirstat/windirstat/tree/release/v2.9.3).

Артефакт принятого прогона: tests/runs/20261104-081657/benchmark.json. Скрипт повторения: tests/Compare-Engines.ps1. История первых отладочных запусков не принимается за отдельный независимый benchmark.

Набор: 12 000 файлов по 4096 байт, глубокий каталог с русским именем и файлом 7777 байт, пустая папка, обычный файл 1 MiB и второй hardlink на него, sparse-файл логического размера 64 MiB без выделенного содержимого, junction наружу и junction-цикл. Чужие пользовательские файлы в сравнении не использовались.

## Скорость, память, отмена

- gdu: 0.117 / 0.205 секунды, наблюдавшийся working set 16.25 / 16.73 MiB.
- WinDirStat: 0.407 / 0.395 секунды, наблюдавшийся working set 42.42 / 28.07 MiB.
- Оба завершённых запуска каждой программы вернули exit 0. Видимое главное окно при опросе процесса не обнаружено.
- Принудительная отмена через завершение процесса: около 4.80 ms для gdu и 4.11 ms для WinDirStat после запроса остановки. Готовый частичный экспорт не получен. Это проверка внешней остановки процесса, не доказательство graceful cancellation/resume.

Файлы были только что созданы, системный файловый кэш не сбрасывался. Это малый fixture и повторные запуски, а не холодный benchmark всего HDD или доказательство превосходства на любых дисках. Память опрашивалась с интервалом, цифры не являются точным OS peak и не включают последующий импорт SmartClean.

## Точность

Ожидаемый логический размер по путям: 118365793 B. Выделенное содержимое по путям: 51257344 B. После удаления повтора file ID внутри области: 50208768 B.

gdu экспортировал dsize=118365793 B и для sparse-файла dsize=67108864 B. Его Windows-реализация подставляет info.Size() вместо allocation и возвращает нулевую inode identity: [официальный код dir_other.go](https://github.com/dundee/gdu/blob/v5.38.0/pkg/analyze/dir_other.go). Отдельно asize пустого каталога добавляет служебный sentinel 512 B. Следовательно, общее обещание проекта про однократный учёт hardlinks не применимо к этой Windows-ветке так же, как к Unix.

WinDirStat экспортировал ожидаемый logical и physical-per-path размер; sparse allocation отличил от длины. Его экспорт восстанавливает allocation для каждого пути hardlink, поэтому простой экспорт также нельзя назвать уникальным физическим объёмом. SmartClean отдельно нормализует file IDs и получает ожидаемую уникальную сумму. [Оговорка формата экспорта](https://github.com/windirstat/windirstat/wiki/Command-Line-and-CSV).

## Решение

Default первого прототипа — WinDirStat с изолированными portable-настройками, английским машинным CSV и собственным индексом. gdu не используется как источник allocated/unique totals на Windows, несмотря на лучшую скорость малого теста. Собственный raw MFT-парсер не нужен.

WinDirStat не даёт в этом экспорте полноценного списка ошибок доступа. Поэтому SmartClean не объявляет результат полностью проверенным: Status=partial, Coverage=unverified. Отмена не обещает частичный индекс. Лицензия WinDirStat GPLv3+ соблюдается отдельно от архитектурного решения использовать внешний процесс.

Дополнительная интеграционная проверка tests/Verify-Prototype.ps1 прошла 19 содержательных проверок на Windows PowerShell 5.1: размеры/ID, ссылки, глубокие русские пути с пробелами и квадратными скобками, исключение собственного хранилища, сравнение двух наблюдений, запрет смешивания томов, отмена, несовместимый формат, denied-folder и удаление собственного отчёта без удаления исходных данных. Полная проверка exFAT/SMB/cloud/ARM64 и других компьютеров остаётся отдельной работой.
