# SmartClean 0.2 — автоматический разбор дисков

Локальная диагностика дисков Windows с русским меню. Браузер, сервер, Node.js, Python и PowerShell 7 не требуются. На этом этапе пользовательские файлы не удаляются и не перемещаются. Удаление собственных сохранённых отчётов доступно отдельно в истории.

## Главное в версии 0.2

**Пункт 2 сам разбирает последние сохранённые сканы всех дисков.** Он проходит через тяжёлые контейнеры вроде Users/профиль/AppData: в консоли 12 крупнейших веток, в отчёте до 25 конкретных веток от 256 MiB. Не нужно самостоятельно раскрывать каждую папку. Ручной просмотр остался в пункте 8.

Разбор сохраняется в `data/reports/<идентификатор-замера>/`:

- `summary.md` — понятный текст: где сосредоточен объём, кандидаты с последствиями, ссылки и крупнейшие файлы;
- `analysis.json` — те же результаты для программного чтения и разбора ассистентом;
- `links.csv` — карта «путь ссылки → назначение».

Оригинальный `engine.csv` и индекс по-прежнему находятся в `data/snapshots/<идентификатор>/`. Сообщение об отсутствии списка ошибок доступа **не означает отсутствия экспорта или потери результата**. При успешном скане CSV и индекс сохранены; сканер лишь не предоставляет подробный журнал всех пропусков доступа.

В пункте 3 сравниваются последние два совместимых замера одного диска. Если замер только один, интерфейс сразу объясняет необходимость следующего. C: и D: не предлагаются как пара «старый/новый».

Пункт 4 показывает только кандидатов по узким правилам; совпадение пути не доказывает безопасность удаления. Важные базы, история, проекты и целые профили не объявляются мусором. Нулевые каталоги не засоряют список кандидатов.

Junction и символические ссылки читаются через отдельный запрос метаданных Windows без обхода назначения. Жёсткие ссылки — несколько имён одного файла; их повторный учёт исключён отдельно, у них нет единственного «пути назначения». Для старых сканов наличие ссылки известно из индекса, но её назначение проверяется на дату создания отчёта. На другом компьютере текущие местные пути не проверяются под видом путей исходного ПК.

Первый автоматический разбор читает весь сохранённый индекс для поиска крупных файлов и ссылок; повторный использует сохранённый `analysis.json`. Повторного сканирования исходных дисков при этом нет. Обновление разбора/назначений без пересканирования: `-Command Analyze -SnapshotId <id> -Refresh`.

## Запуск

Дважды нажмите **Start-SmartClean.cmd**. Первый запуск показывает физические диски, разделы и тома, предлагает место для результатов. Полный скан начинается после выбора пункта 1 и конкретного тома/каталога.

По умолчанию результаты лежат в `data` рядом со скриптом. На другом компьютере буквы дисков и профиль пользователя определяются заново. Выбирайте для `data` диск с запасом места. Запуск обычно не требует администратора; повышенные права могут расширить доступ и включить ускоренный полный NTFS-скан. Уровень прав сохраняется в замере, сравнение разных уровней запрещено.

Если перенесли только исходные файлы без `tools`, один раз выполните:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Install-Tools.ps1
```

Установка скачивает закреплённый portable WinDirStat с официального GitHub и проверяет SHA-256. Не меняет PATH и системные настройки. Интернет нужен при установке, дальнейшее сканирование локальное. Перед каждым запуском проверяется хеш exe. Требуется доступная полная языковая среда PowerShell; заблокированный корпоративной политикой Add-Type пока не поддерживается.

## Что работает

1. Инвентаризация накопителей, разметки, файловых систем, ёмкости и свободного места. При неизвестном SSD/HDD выводится Unknown.
2. Один read-only скан выбранной области: полный учёт глубоких файлов, обзор до трёх уровней. На экран выводится ограниченное число крупнейших элементов с указанием пропущенных строк.
3. Просмотр сохранённого индекса: номер — раскрыть, `..` — вверх, `t` — дерево, `m` — сменить метрику, `p` — перейти по полному или относительному пути в индексе. Повторный обход файловой системы для навигации не выполняется.
4. Сохранение и сравнение замеров каталогов. Даты UTC в CLI/манифестах. Сравниваются совпадающие компьютер, том, корень, движок, права, метрика и исключения.
5. Отмена клавишей Esc. У WinDirStat export нет гарантированного частичного дерева: сохранится статус cancelled, незавершённый индекс не используется. Во время импорта Esc также останавливает операцию. Ctrl+C прерывает PowerShell; finally останавливает дочерний процесс, если управление возвращено скрипту.
6. История сканов, лимиты количества/объёма собственных результатов и проверка свободного места. Лимиты не запускают автоматическое удаление: история позволяет удалить выбранный собственный замер.

Очистка кэшей — следующий этап полной v1 после конкретных правил и согласований. Дубли между дисками и переносы — v2. Фоновый процесс и автоматическое недельное расписание не устанавливаются.

## Что означают размеры

- Логический размер — длина содержимого файлов по путям.
- Выделено, сумма путей — данные Physical Size экспорта. Для hardlinks повторные пути могут содержать одни и те же байты.
- Без повторов file ID — повторная allocation исключена в пределах одной области/тома. При неизвестном ID уникальная сумма становится `?`. Распределение такой суммы по папкам зависит от первого встретившегося пути и не означает, что удаление папки освободит указанное место.
- Junction, directory symlink и точки монтирования не раскрываются. Сам корень-ссылка отклоняется: выберите его фактическое назначение. Облачные placeholders не скачиваются намеренно; отдельная полноценная проверка облачных провайдеров ещё не выполнена.
- Общая занятость тома включает системные метаданные и другие неохваченные зоны. Сумма файлов не обязана ей равняться.

WinDirStat не экспортирует все ошибки перечисления/доступа. Поэтому успешный обход имеет **Status=partial / Coverage=unverified**: дерево готово, но полнота недоказана. Это обозначено на экранах. Исчезнувшая в следующем замере папка отображается как «не наблюдается», а не доказанно удалённая. Из роста нельзя доказать конкретный процесс-виновник.

## Команды без меню

```powershell
.\SmartClean.ps1 -Command Inventory -Json
.\SmartClean.ps1 -Command Scan -Path C:\ -Json
.\SmartClean.ps1 -Command Scan -Path D:\ -Json
.\SmartClean.ps1 -Command History -Json
.\SmartClean.ps1 -Command Analyze
.\SmartClean.ps1 -Command Analyze -SnapshotId <id> -Json
.\SmartClean.ps1 -Command Overview -SnapshotId <id>
.\SmartClean.ps1 -Command Browse -SnapshotId <id>
.\SmartClean.ps1 -Command Compare -Before <старый-id> -After <новый-id> -Json
```

`-DataRoot <полный-путь>` выбирает другое хранилище для данного запуска. `-CancelFile <путь>` позволяет внешнему процессу остановить скан созданием указанного файла. `-TimeoutSeconds` по умолчанию 3600. Exit 0 — результат доступен (в том числе unverified), 1 — ошибка, 2 — отмена. Для еженедельного ручного контроля повторяйте одинаковые команды Scan и Compare. Настройку планировщика добавим отдельно.

## Модули и формат

`modules/Core.ps1` — настройки, хранилище и история; `Inventory.ps1` — карта оборудования; `Scanner.ps1` — адаптер WinDirStat; `Reports.ps1` — дерево и сравнение; `Analysis.ps1` — автоматический разбор, правила-кандидаты и экспорт отчётов; `Menu.ps1` — интерфейс. `src/SnapshotIndex.cs` компилируется штатным Add-Type, без SDK. Читает CSV потоком, держит в памяти индексы каталогов и смещения дочерних записей; файлы читаются из бинарного индекса по запросу. `src/NativeLinks.cs` отдельно читает метаданные reparse points; он не изменяет ссылки и не обходит их назначения.

Каждый замер неизменяем: manifest.json, inventory.json, engine.csv, nodes.bin, index.bin. У неудачного/отменённого запуска индекс может отсутствовать или быть неполным; открыть его нельзя. SchemaVersion=1. Подробный контракт: docs/CONTRACTS.md.

## Проверка и зависимости

Рабочий запуск проверен на Windows 10 x64 / Windows PowerShell 5.1. x86/ARM64 выбираются по архитектуре ОС, но на этих устройствах ещё не испытывались. FAT/exFAT, сетевые каталоги и другие ПК не считаются проверенными только из-за наличия поддержки в стороннем сканере. Нестандартные NTFS case-sensitive каталоги и чрезвычайно длинные пути требуют дополнительной проверки.

Сравнение gdu и WinDirStat действительно выполнено на одинаковом тестовом наборе; результаты и оговорки в research/ENGINE-DECISION.md. gdu быстрее на тесте, но его Windows-код не сообщает реальную allocation и hardlink ID. Поэтому default — WinDirStat + отдельная нормализация индекса, а не gdu.

Повторяемая проверка:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tests\Verify-Prototype.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tests\Verify-Analysis.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tests\Compare-Engines.ps1
```

Тесты создают свои данные только в tests/runs. Benchmark создаёт 12 000 файлов; не запускается автоматически. Сторонние лицензии и пути к исходникам установлены в tools соответствующего продукта. WinDirStat — GPLv3+, gdu — MIT; готовую сборку нельзя распространять без соблюдения их условий. Исходные файлы SmartClean не содержат кода сторонних сканеров.
