# SmartClean: направление разработки

Дата исследования: 2026-11-02. Цель — скорость повторной работы, проверяемость результатов,
отзывчивый каталог и надёжное управление большой коллекцией на обычном ПК.
«Самая высокая скорость» — критерий для измерения, не обещание без тестов.

## Слои и этапы

| Слой | Данные/результат | Состояние |
|---|---|---|
| Источники | Локальные пути, исключения, медиа, идентификаторы файлов | 0.1 |
| Точные копии | Размер, частичный хэш, SHA-256, жёсткие ссылки | 0.1 |
| Каталог | Превью по запросу, метаданные, формат, пропорции, метки | 0.1 |
| Похожие фото | dHash, BK-tree, сравнение пар | Ограниченный прототип |
| Анализ качества | Резкость, экспозиция, повреждения, оценка качества по компонентам | План |
| Видео | Кадры по сценам, временные подписи, совпавшие интервалы, аудиоотпечатки | План |
| Люди | Лицо → embedding → группа → имя/исправления | План |
| Места | GPS/точность/источник → место; отдельно визуальная сцена | План |
| Объекты | Объект, confidence, bbox и таймкод для видео | План |
| Поиск по смыслу | Многоязычная модель image/text embeddings, ANN-индекс | План |
| Текст и речь | OCR, транскрипт, speaker, сегменты с таймкодами | План |
| Очистка | План, сохранённая копия, повторная проверка, карантин, undo | План |

Дополнительные полезные разрезы: время съёмки с источником и часовым поясом,
событие/серия, камера/объектив, RAW+JPEG, Live/Motion Photo, скриншоты,
панорамы, вертикальные/квадратные/горизонтальные кадры, длительность, разрешение,
кодек, HDR, FPS, звук, битрейт, размер и фактическая доступность диска.
Разрешение/битрейт сами по себе не доказывают лучшее качество; исходник и монтаж
могут иметь разную ценность. Нельзя автоматически удалять похожие фото/версии/серии.

## Модель данных следующего этапа

- FileLocation — физический файл, volume ID, file ID, состояние доступности.
- Content — содержимое и полный digest; вычисления могут разделяться точными копиями.
- Asset/AssetRelation — исходник, экспорт, редакция, RAW+JPEG, серия, фрагмент.
- AnalysisResult — версия модели, SHA-256 весов, параметры, input digest, версия декодера.
- FaceObservation — bbox, confidence, embedding, качество, file/frame/timecode.
- Person и FaceCluster — самостоятельные сущности; ручные merge/split/ignore сохраняются
  отдельно от автоматических предложений и не исчезают после повторного анализа.
- Place — GPS, точность и происхождение. Визуальная сцена «пляж» не означает конкретный город.
- ObjectObservation/Scene — имя, confidence, bbox/time interval, модель/версия.
- TextSegment/Speaker — OCR/речь и позиция; человек в кадре и говорящий различаются.
- Job/Task/Lease/Attempt — долговечная очередь, retries, timeout, heartbeat, resume.
- CleanupPlan/Operation — source/keeper, доказательства проверки, причина,
  состояние каждого шага и журнал восстановления.

## Производительность

0.1 намеренно использует один фоновый исполнитель: это предсказуемая отправная
точка для HDD, а не окончательный предел. Перед увеличением параллельности нужны замеры.

1. Нативный быстрый обход файловой системы. На Windows отдельный адаптер MFT/USN
   с проверкой прав, volume ID и fallback на scandir; обычный переносимый обход остаётся.
2. Очереди отдельно для inventory, hashing, decode, faces, embeddings, indexing.
   Квоты на RAM/VRAM, число декодеров, IO на **физический** диск, приоритет foreground.
3. HDD: последовательные чтения; SSD: ограниченная параллельность. Физическое
   устройство определяется отдельно от буквы раздела. Настраиваемая пауза/лимит скорости.
4. Метаданные дешёвые и ранние; модели запускаются над уменьшенным кадром и батчами.
   Один decode/frame cache для нескольких моделей, один результат на одинаковое содержимое.
5. Версионируемые результаты, атомарные записи, дедупликация задач, повтор после сбоя.
   Полный оригинал не транскодируется ради каждого поиска или нового имени человека.
6. ANN-индекс для embeddings, BK-tree/LSH для перцептивных отпечатков;
   временное выравнивание для видео. Без безусловного N² сравнения всей коллекции.
7. Пагинация/виртуализация UI, фоновые превью, ограниченный LRU-кэш и явный бюджет диска.
8. Профили CPU / экономичный GPU / производительный GPU, с fallback и показом фактического backend.

Метрики: files/s и bytes/s на первом и повторном проходе, physical bytes read,
доля кэша, p50/p95 задержки каталога, пик RAM/VRAM, размер DB/preview cache,
CPU/IO foreground, время отмены/восстановления, false positive/negative по размеченному набору.
Фикстуры не заменяют замеры на реальных HDD/SSD. Не сканировать личные диски автоматически.

## Выбор моделей и библиотек

- Python/SQLite — переносимое управляющее ядро первой версии; критические участки
  сравниваются с нативными библиотеками, прежде чем переписывать весь стек.
- FFmpeg/ffprobe — адаптер видео с таймаутом, лимитами и управлением процессом.
- ONNX Runtime: провайдер под фактическое оборудование. На современных Windows
  официально рекомендуется WinML; DirectML поддерживается, но новые функции переходят
  в WinML. Для Windows 10 нужен совместимый отдельно проверенный путь ORT.
- Лица: detector + embedding-модель, кластеризация с подтверждением, порог по качеству.
  Отдельно проверять лицензии кода **и весов**, целевую RAM/VRAM, точность на семейных
  фото/видео, повороты/возраст/слабый свет, исправления групп и повторяемость результата.
- Смысл: сравнить многоязычные CLIP/SigLIP-подобные модели на русских запросах и
  личном тестовом наборе; размер модели выбирается по recall/latency/VRAM.
- Объекты/сцены дополняют семантический поиск. Не выбирать детектор только по новизне
  или маркетинговому benchmark; измерять нужные классы и условия.

Модели пока не выбраны окончательно, не скачаны и не подключены. «Актуальный» не равно
«обязательно самый большой». Точный комплект фиксируется по результатам benchmark,
с лицензией, checksum и версией. Новая модель не переписывает ручные метки.

## Безопасная очистка

До любых изменений: отдельный reviewable план; свежий полный хэш сохраняемого и
удаляемого экземпляра, проверка доступности и правил сохранения. Для byte-for-byte
гарантии — последовательное сравнение перед операцией. Similarity не является доказательством.
Нельзя удалять последнюю копию, принимать hardlink за освобождаемый объём,
удалять исходник после непроверенного междискового копирования или перезаписывать цель.
Первая реализация — карантин с журналом и восстановлением. Реальное удаление
отдельным действием после сверки. До реализации этого контура в 0.1 нет API изменения оригиналов.
