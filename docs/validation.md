## Замер кэша и первого прохода

Воспроизводимый сценарий: `python tests/benchmark.py`.
200 искусственных файлов по 256 КиБ: 100 пар, 50 МиБ логического объёма,
временная папка, содержимое создано непосредственно перед измерением.
Влияние файлового кэша ОС и фоновой нагрузки не устранено; это не benchmark
скорости последовательного чтения диска и не прогноз для терабайтной коллекции.

Последний запуск после пакетной записи хэшей и одного чтения небольших кандидатов:

| Проход | Время | Новых полных хэшей | Из кэша инвентаря | Ошибки |
|---|---:|---:|---:|---:|
| Первый | 14,313 с | 200 | 0 | 0 |
| Повторный | 0,546 с | 0 | 200 | 0 |

Начальный вариант с отдельной транзакцией для каждого digest и двумя открытиями
каждого небольшого кандидата в одном предыдущем запуске занял 22,330 с.
Это наблюдения отдельных запусков, а не статистически доказанный коэффициент ускорения.
Профилирование 20 файлов показало, что большая часть времени была в `open`,
а не в SHA-256; причина задержки открытия отдельно не устанавливалась.
Результат последнего замера сохраняется в `output/benchmark.json`.

## Границы проверки

Проверены Windows/локальная файловая система. Не проверены другие ОС, сетевые
папки, длительная работа с миллионами файлов, длительные видео и фактическое
декодирование ffmpeg/ffprobe: на PATH этого ПК инструменты не обнаружены.
Прототип поиска похожих фото имеет лимиты и не заменяет модель сходства.
Распознавание лиц, объекты и семантический поиск пока не реализованы и не тестировались.
