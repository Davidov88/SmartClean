# SmartClean

**Состояние: незавершённый прототип.** Поиск точных совпадений и сохранение хэшей есть;
полезные фильтры/групповой выбор в разделе дублей, удаление и самостоятельная desktop-поставка
ещё не готовы. Пустая выдача при сбое запроса не доказывает отсутствие сохранённых совпадений.

Текущий приоритет и критерии следующего выпуска: **[план SmartClean](docs/ROADMAP.md)**.
Опыт каталога [media-cat](https://github.com/createsens/media-cat) учтён в плане;
его база, оригиналы и ручная разметка этим проектом не меняются.

Локальный каталог фото и видео на нескольких дисках. Новый самостоятельный проект.
Оригиналы остаются на местах. Задачи запускаются пользователем; автоматического обхода при старте нет.

## Запуск

Windows: двойной щелчок по `SmartClean.vbs` — отдельное окно без вкладок и адресной строки.
Используется установленный движок Edge (или Chrome); это desktop-оболочка веб-интерфейса,
а не полностью нативный UI. `Start-SmartClean.cmd` также запускает это окно и при необходимости устанавливает зависимости.
Повторный запуск подключается к уже работающему сервису. Закрытие окна не останавливает сканирование.
На Windows окно и сервис запускаются через две задачи Планировщика текущего пользователя
`SmartClean-Service-*` и `SmartClean-Window-*`. У них нет расписания/автозапуска и лимита
длительности. Это отделяет их от дерева процессов Codex. Права администратора не запрашиваются.
После прерывания завершённого обхода доступно «Продолжить сравнение»: сохранённые SHA-256
используются повторно без нового обхода источников. Новые файлы учитываются обычным сканированием.
Ручной доступ при необходимости: <http://127.0.0.1:8765>.

Другие ОС / ручной запуск (Python 3.11+):

```sh
python -m venv .venv
# Активируйте окружение своей оболочки.
python -m pip install -e .
python -m smartclean --data-dir /absolute/path/to/catalog-data --port 8765
```

Данные по умолчанию: `.local/` относительно рабочей папки. Можно изменить через
`--data-dir` или `SMARTCLEAN_DATA_DIR`. Для переносимой установки используйте абсолютный путь.
Личные пути не входят в код или общие настройки. Пустая установка не имеет источников и личных исключений.

1. Открыть «Источники и исключения», добавить папки/диски, настроить исключения и сохранить.
2. «Сканировать»: инвентаризация и сравнение точных дублей по содержимому.
3. «Анализ и возможности» → «Запустить анализ»: свойства изображений и видео, dHash фото.
4. В каталоге доступны поиск, тип, формат, пропорции и сортировка. В карточке можно назначать метки.

## Реализовано в 0.1

- SQLite WAL, пакетная запись инвентаря, пагинация и ограниченное потребление памяти при обходе.
- Обход через `scandir`, игнорирование ссылок/junctions, offline/cloud-placeholder атрибутов и каталогов данных приложения.
- Настраиваемые источники, исключённые пути, имена папок, системные исключения и минимальный размер.
- Найденные файлы появляются во время сканирования; показаны этап, прошедшее время,
  средняя скорость, пройденные папки/источники и ошибки. Точный процент и ETA не выдумываются до завершения обхода.
- Видимость источников материализуется в SQLite при изменении настроек; статистика
  использует покрывающий индекс. Опрос UI последовательный, без наложения запросов.
- Windows extended paths для обхода/статистики/хэшей поддерживают пути длиннее MAX_PATH.
- Размер → SHA-256 выборки (начало/середина/конец) → полный SHA-256 кандидатов.
  Кандидаты до 1 МиБ хэшируются целиком за одно открытие: на Windows задержка
  открытия файла может быть дороже чтения его содержимого.
- Кэш по размеру, mtime, ctime, устройству и file ID; проверка до и после хэширования.
- Отмена и повторный запуск: завершённые хэши и метаданные используются повторно.
  После закрытия незавершённые задачи отмечаются interrupted. Обход папок повторяется;
  это не сохранение точного курсора обхода/позиции в большом файле.
- Жёсткие ссылки не считаются независимыми физическими копиями. Оценка повторного
  содержимого не равна гарантированно освобождаемому месту.
- Отсутствующие файлы помечаются после полного успешного обхода источника.
  Недоступный или частично прочитанный источник сохраняет последний индекс; каталог может содержать offline-записи.
- Pillow: размеры, ориентация EXIF, формат, пропорции, часть EXIF, dHash, превью по запросу.
- ffprobe/ffmpeg (если установлены): свойства видео и первый кадр по запросу. Нет автоматического скачивания.
- Фото сравниваются по dHash и приблизительным пропорциям через BK-tree.
  Лимит первого прототипа — 20 000 фото / 300 пар, явно показан в интерфейсе.
  Однотонные изображения дают ложные совпадения; точные хэш-дубли исключаются из этой выдачи.
- Ручные метки людей, мест, объектов, событий; поиск по пути и меткам.
- HTTP только на loopback, проверка Host, токен для изменений, проверка Origin, CSP.

## Ещё не реализовано

Автоматические лица и группы людей, GPS/карта, объекты/сцены, семантический поиск,
OCR, распознавание речи, похожие видео, карантин/удаление/восстановление,
MFT/USN, watcher, лимит/очистка кэша, адаптивная очередь по физическим дискам и GPU.
Они показаны как следующие этапы, а не как работающие функции. См. `docs/architecture.md`.

RAW/HEIC перечисляются в каталоге; доступность декодирования зависит от установленных кодеков.
Расширение определяет попадание в инвентарь, фактический формат устанавливается анализом.
Неизвестные/повреждённые файлы остаются в каталоге с ошибкой анализа.
В текущей версии нет чтения медиапотока, внешнего доступа, облачной загрузки и изменения оригиналов.
Индекс содержит локальные пути и метки: папку данных следует хранить как личные данные.

## Проверка

```sh
python -m unittest discover -s tests -v
```

Проверяются точные дубли, коллизия частичного отпечатка, кэш и его инвалидирование,
исключения до обхода, изменения/исчезновение файлов, offline-источники, жёсткие ссылки,
отмена хэширования, метаданные/превью, поиск похожих фото и защита HTTP-изменений.
